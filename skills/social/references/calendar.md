# Social Calendar

The calendar is generated by a script so dates, weekdays, cadence and pillar proportions are exact; the model fills the creative columns. Reference: `${CLAUDE_PLUGIN_ROOT}/skills/social/references/calendar/occasions.md` — commercial, seasonal and memorial dates to plan around, with verification status.

## 1. Inputs (from `references/strategy.md`, or ask)
Period (start–end, ≤ 2 years) · pillars with shares · platforms with posts per week, days and time · brand dates (launches, sales, birthdays) · language of the calendar (uk/en). Missing strategy → take pillars and cadence from the user's answer or the strategy tiers, and state them.

## 2. Generate
```
node "${CLAUDE_PLUGIN_ROOT}/scripts/calendar.mjs" --start 2026-12-01 --end 2027-02-28 \
  --pillars "Користь:40,Продукт:30,Спільнота:20,Промо:10" \
  --cadence "instagram:3#19:00,stories:daily#10:00,telegram:5@mon-fri#09:00,tiktok:4#18:30" \
  --extra deliverables/social/<slug>/dates.json \
  --csv deliverables/social/<slug>/calendar.csv --ics deliverables/social/<slug>/calendar.ics
```
- Cadence item: `platform:N[@days][#HH:MM]` — N 1–7 or `daily`; days `mon+wed+fri` or `mon-fri`; default days are spread evenly (3 → Mon/Wed/Fri).
- `--formats "instagram=reel+carousel+reel+post"` sets the rotation per platform (defaults: Instagram reel → carousel → post; TikTok video; Telegram post; Threads text; LinkedIn post → carousel; YouTube short).
- `--extra` = JSON list `[{ "date": "2026-12-12", "name": "День народження бренду", "note": "розіграш" }]` for launches, sales, brand dates and observances you verified.
- Holidays: Ukrainian public holidays (Labour Code Art. 73) are added as all-day rows; under martial law they are working days — they are content occasions, not days off. `--no-holidays` to skip; `--holidays <file>` for another country's data in the same format.
- Pillars are assigned per platform by smooth weighted round-robin, so each platform's mix tracks the shares exactly over time. Posts with a promo pillar on a memorial day are flagged in the JSON summary and the notes column — move or replace them.
- ICS uses `TZID=Europe/Kyiv` with an embedded EU daylight-saving rule; `--tz floating` writes local times without a zone (use it if Ukraine's clock rules change).
- The JSON summary prints counts per platform and pillar, holidays in range and warnings. Exit 2 = input error with the reason.

## 3. Fill the creative columns
For each row fill `topic`, `hook`, `cta` (and `notes` for assets needed):
- Topic follows the pillar and the occasion of the week; series beat one-offs (e.g. «Розбір помилки тижня» every Tuesday).
- Hooks per `references/posts.md` / `references/video-scripts.md`; CTA matches the post's job (save, share, comment, DM, buy).
- Plan backwards from launches and sales: teaser (−7 to −3 days) → reveal → proof → deadline reminder → thank-you/results.
- Holidays: decide per tone (`tone` in the data file and `occasions.md`): celebratory → greeting or themed post; civic → dignified, low-key; memorial → remembrance only or silence, no promo, no humour.
- Batch: write 1–2 weeks at a time with the user's approval before the rest; keep 2–3 evergreen posts in reserve for outages and unexpected days.
- Statuses: `idea → draft → design → approved → scheduled → published`. Owners in `notes` if several people work on it.

## 4. Checks
- [ ] Script ran in this session; the summary matches the agreed cadence and pillar shares.
- [ ] No promo on memorial days; occasions checked against `occasions.md` (dates that move each year verified for that year).
- [ ] Every row has topic, hook and CTA (or is marked reserve); no two consecutive posts on one platform with the same pillar and format unless intended.
- [ ] Launch and sale dates match the brief; promo terms and deadlines written exactly.
- [ ] CSV opens correctly in Excel/Google Sheets (UTF-8 with BOM, Cyrillic intact); ICS imports into Google Calendar/Outlook.

## 5. Output
```

```
